MEETING FOLLOW-THROUGH

New to this app? Here is how it works.

A salesperson has meeting notes and CRM records. The agent decides what follow-through is justified: update relevant deals, create missing tasks, leave records unchanged, or explain what needs clarification. All companies, people, and notes in this lab are invented.

A model request sends the conversation so far. The response may contain text, requested tools, or both. The application validates and executes those tools, adds their results to the conversation, and asks the model what to do next. The exact messages and available tool definitions are visible in each model call below.

Model call
The AI reads messages and chooses a response or tool requests.

Tool call
The application reads CRM records or validates and writes a change.

Database change
An actual local write, shown separately from what the model proposed.

Completed means the agent loop ended. It is not an evaluation score or a guarantee that the model was correct. No changes or a request for clarification can be a valid result. Review the response, evidence and saved changes to judge the outcome.

No email is sent and no external CRM is modified. Failed runs can still have saved changes; the before/after snapshots show what actually happened. Offline runs use fixture responses and are not evidence of real model behavior.
