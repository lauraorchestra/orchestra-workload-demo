MEETING FOLLOW-THROUGH

New to this app? Here is how it works.

A salesperson has meeting notes and an outdated CRM. This agent reads the notes, finds the right deal, updates it, and creates a local follow-up task. All companies, people, and notes in this lab are invented.

  1. Extract meeting facts. One model request turns the notes into facts and uncertainties.
  2. Reconcile the deal. The main agent asks for CRM tools, reads their results, and decides what to do next. This conversation usually takes several model requests.
  3. Assess deal readiness. A separate model request checks the sales stage against the meeting, deal, and history before a deal update is saved.
  4. Draft a follow-up. A separate model request writes a task. The main agent then asks a tool to save that task in the CRM.

These are four types of work, not four consecutive messages. Assessment and drafting happen inside the main agent’s tool loop. A model request sends the conversation so far; a model response may contain text, tool requests, or both. The application executes those tools and returns their results in the next model request.
